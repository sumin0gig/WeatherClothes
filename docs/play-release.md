# Google Play 출시 체크리스트

## 0. 지금 상태

- 패키지명: `com.developer_cm.weatherclothes` / 앱 이름: `옷벤토리` (`android/app/src/main/res/values/strings.xml`)
- 권한: `INTERNET`, `ACCESS_COARSE_LOCATION`, `ACCESS_BACKGROUND_LOCATION` (정밀 위치 없음)
- 서버·계정·분석·광고·푸시 없음

## 1. 개발 중 — 내부 테스트

- [ ] 업로드 키 만들기, `android/app/build.gradle`의 `release` 서명 설정 (지금은 템플릿 기본값인 debug 키로 서명됨 — 출시 전 반드시 교체)
- [ ] `cd android && ./gradlew bundleRelease` → `android/app/build/outputs/bundle/release/app-release.aab`
- [ ] Play Console에서 앱 만들기 → **내부 테스트** 트랙에 AAB 업로드 → 본인 계정으로 설치해서 사용

## 2. 프로덕션 접근 여부 확인

- [ ] 새 앱 대시보드에서 **테스트 및 출시 → 프로덕션** 메뉴가 바로 열리는지 확인
  - 열리면 3단계로
  - 막혀 있으면 비공개 테스트 필요: 테스터 **12명 이상, 14일 연속** 참여 후 프로덕션 접근 신청
  - 같은 테스터에게 부탁해도 되지만, 이 앱의 비공개 테스트에 새로 참여해야 하고 14일은 처음부터

## 3. 정책 양식

### 백그라운드 위치 권한 선언서

- 핵심 기능 설명 예시:
  > 홈 화면 위젯이 사용자가 지금 있는 곳의 체감온도에 맞는 옷차림을 보여줍니다. 사용자가 앱을 열지 않아도 이동한 지역의 날씨로 위젯이 갱신되려면 백그라운드에서 대략적인 위치가 필요합니다.
- [ ] **시연 영상** (YouTube 링크)
  1. 첫 실행 사전 고지 화면 (`OnboardingScreen` — 문구는 `DISCLOSURE_TEXT`)
  2. 시스템 권한 → "항상 허용"
  3. 홈 화면에 위젯 추가
  4. 에뮬레이터 Extended controls → Location에서 다른 도시로 변경 → 위젯이 그 지역 날씨로 바뀌는 장면 (위젯 갱신 주기가 1시간이라, 영상에서는 앱을 한 번 열었다 닫아 즉시 갱신시키면 된다)

### 데이터 보안

| 항목 | 답변 |
|---|---|
| 수집 데이터 | 위치 → 대략적인 위치 |
| 용도 | 앱 기능 |
| 공유 | 안 함 (날씨 조회를 위해 좌표를 Open-Meteo에 보내지만 "서비스 제공자"로의 전송) |
| 전송 중 암호화 | 예 (HTTPS) |
| 삭제 요청 | 앱 삭제 시 기기에서 함께 삭제. 서버에 저장하지 않음 |
| 계정 | 없음 |
